# mlpub-bundle 规格

## 目的

下载队列中**未成功**任务（排队、下载中、失败、停止、取消）的 **`.mlpub`**（UTF-8 JSON）导出与拖回导入、保存到已存在包时的合并去重，以及主窗口关闭时的三键确认。与缩略图浏览能力 `browse-download-ux` 正交。

本规格由变更 `unfinished-download-mlpub` 归档后同步入主库。当前实现首版仅将**具备有效 `http`/`https` 直链**且**无子图**的项写入 `tasks`；导入时未知站点或非法 URL 的任务跳过并汇总提示（见 `UnfinishedDownloadMlpub`）。

## 需求

### 需求：未完成任务包格式（`.mlpub`）

系统必须定义**唯一**的机器可读格式，用于**未成功下载任务**的导出与再次导入。文件扩展名必须为 **`.mlpub`**，内容为 UTF-8 JSON（不要求 BOM）。根对象必须包含：

- `"schema"`：字面量 **`MoeLoaderP.UnfinishedDownloadTasks`**
- `"version"`：整数 **`1`**（仅在破坏性变更时递增）
- `"exportedAt"`：可选，ISO-8601 UTC 字符串，用于审计
- `"tasks"`：任务对象数组（见下一条需求）

凡通过**拖放导入**到下载面板的文件，若不是 **`.mlpub`**，或其 JSON 无法解析、或 `schema` / `version` 不满足上文约定，则必须拒绝导入。**写入**与**导入**仅支持本约定；v1 不要求与其它扩展名或历史 `schema` 字面量兼容。

#### 场景：合法包被识别

- **当** 文件扩展名为 `.mlpub`，且 UTF-8 JSON 根对象满足 `schema == "MoeLoaderP.UnfinishedDownloadTasks"` 且 `version == 1`  
- **则** 应用必须将其视为可导入的包（仍可对单条任务做校验）

#### 场景：扩展名错误则拒绝

- **当** 用户将扩展名不是 `.mlpub` 的文件拖到下载列表区域  
- **则** 不得入队任务（无效扩展名不得呈现为可 `Copy` 的拖放效果）

#### 场景：schema/version 错误则拒绝

- **当** `.mlpub` 能解析为 JSON，但 `schema` 或 `version` 与支持的契约不符  
- **则** 必须拒绝导入，且不得部分入队畸形包（须向用户展示明确错误信息）

### 需求：任务记录字段（跨会话最小闭环）

`tasks` 中每个元素必须为 JSON 对象，至少包含在后续会话中重新入队下载所需的数据，包括：

- **`siteShortName`**（字符串）：条目所属站点的 `MoeSite.ShortName`
- **`downloadUrl`**（字符串）：主要下载目标 URL（导出时若有已解析直链则写入；若仅有 `ResolveUrlFunc`，则以设计为准可写最佳已知直链，或允许 `downloadUrl` 为空并在后续版本再解析详情页）
- **`referer`**（字符串，可选）：下载请求的 HTTP Referer
- **`detailUrl`**（字符串，可选）：需再次解析时的详情页 URL
- **`id`**（数字或字符串）：站点作品 ID；无则按设计使用 `0` 或空约定
- **`title`**（字符串，可选）：展示标题
- **`localFileShortNameWithoutExt`**（字符串，可选）：期望本地主文件名（无扩展名）
- **`dlStatusAtExport`**（字符串，可选）：导出时 `DownloadStatus` 枚举名的快照（如 `Downloading`、`Failed`），用于诊断；导入时仍应以 **`WaitForDownload`** 入队（除非设计另有规定）

导出管道可增加字段以利向前兼容；导入必须忽略未知字段。

#### 场景：导出产生可解析包

- **当** 用户导出未成功任务且存在至少一条可导出条目  
- **则** 写入的 `.mlpub` 必须符合本条对根对象与 `tasks` 的形状要求，且为 UTF-8 可解码的 JSON

### 需求：下载列表右键——导出未成功任务

下载列表的上下文菜单（`DownloaderControl` 或等价控件）必须提供命令（中文示例：**「导出未成功任务」**），用于写入 **`.mlpub`**。导出集合必须包含当前下载列表中 `DlStatus` **不属于**成功终态的**每一条** `MoeItem`，具体**必须包含** **`Failed`**、**`Downloading`**、**`WaitForDownload`**、**`Stop`**、**`Cancel`**，且**必须排除** **`Success`** 与 **`Skip`**。若条目存在一条或多条 **`ChildrenItems`**（多图父项），v1 **不得**写入包内（包中不定义嵌套 `children[]`）。若经上述过滤后**可导出条数为 0**，命令必须给出非破坏性提示且**不得**写文件。

#### 场景：导出包含进行中的下载

- **当** 队列中存在至少一条可导出的 `Downloading` 或 `WaitForDownload` 项（无 `ChildrenItems`），且用户执行导出命令  
- **则** 这些条目必须出现在导出 `tasks` 数组中，并与可导出的 `Failed` / `Stop` / `Cancel` 项一并写入

#### 场景：存在可导出未成功项

- **当** 队列中存在一条或多条可导出的未成功项，且用户执行导出命令  
- **则** 系统必须提示保存路径（或使用文档约定的默认命名），并写入一个 `.mlpub`，其 `tasks` 数组**恰好**为该导出集合

#### 场景：仅多图父项未成功

- **当** 队列中每一条未成功行均为多图父项（v1 不可导出），且用户执行导出命令  
- **则** 不得写入 `.mlpub` 文件，并须告知用户按当前规则无可导出内容

#### 场景：保存到已存在合法 `.mlpub` 时合并任务

- **当** 用户选择的保存路径上已存在文件，该文件为合法 UTF-8 JSON、且 `schema` / `version` 受支持，且用户确认保存  
- **则** 系统必须读取已有 `tasks`，将每条新任务记录与已有任务按设计去重（相同 `siteShortName` 且 Trim 后相同 `downloadUrl`；若 `downloadUrl` 为空则按设计的备用键）后追加，写回**合并后**的单一 `tasks` 数组，且不得丢弃与本次导出无关的既有条目

#### 场景：路径已存在但不是合法包

- **当** 用户选择的路径上已有文件，但该文件不是合法的 `.mlpub`（schema 错误、JSON 损坏等）  
- **则** 不得静默用导出数据覆盖该文件；必须报错，并中止或提示另选路径（具体交互以设计为准）

#### 场景：无可导出内容

- **当** 每一行均为 `Success` 或 `Skip`，或列表为空，且用户执行导出命令  
- **则** 不得写入 `.mlpub`，并须告知用户无可导出内容

### 需求：主窗口关闭——仍有未完成工作时的三键确认

当用户尝试关闭主窗口，且下载队列中**至少存在一条** `DlStatus` 为 **`Failed`**、**`Downloading`**、**`WaitForDownload`**、**`Stop`** 或 **`Cancel`** 的条目时，系统必须弹出**三键**确认（例如 WPF `MessageBox`，**是 / 否 / 取消**）。**多图父项**（`ChildrenItems` 非空）若处于上述状态之一，**必须**计入「未完成」以弹出对话框，即便 v1 **不能**将其写入包内。正文必须说明：**是** = 先走保存流程导出**可序列化**的未成功任务再关闭；**否** = 不导出直接关闭；**取消** = 中止关闭。若用户选**是**但在保存对话框中取消保存，则应用**不得**退出。若用户选**否**，则关闭窗口且**不写**包。

#### 场景：下载中关闭出现提示

- **当** 至少有一条为 `Downloading` 或 `WaitForDownload`，且用户关闭窗口  
- **则** 必须在退出前出现三键提示（测试可覆盖时除外）

#### 场景：取消关闭

- **当** 用户在关闭提示上选择**取消**  
- **则** 必须中止关闭操作

### 需求：下载列表拖放——仅导入 `.mlpub`

下载面板（`DownloaderControl` 或其 `ListBox` 宿主）必须**仅**按上文定义处理 **`.mlpub`** 的拖放。对合法文件执行拖放后，必须将其中每条合法任务追加到下载队列，状态为 **`WaitForDownload`**（或等价状态），以便既有定时器/下载管线处理。非 `.mlpub` 文件必须忽略或明确拒绝，且无副作用。

#### 场景：拖入合法包

- **当** 用户将一个或多个通过 schema 校验的 `.mlpub` 拖到下载列表上  
- **则** 每个包含的任务必须加入队列；不得执行文件内脚本（仅 JSON）

#### 场景：拖入非包文件

- **当** 用户拖入 `.jpg`、`.txt`、无 `.mlpub` 扩展名的 `.json` 或可执行类型等  
- **则** 不得从这些拖放中入队下载

### 需求：安全与健壮性

导入不得执行嵌入脚本；仅允许 JSON。导入必须在发起网络请求前按保守规则校验 URL（例如仅 `http`/`https`）；非法 URL 必须跳过，并记录日志或向用户汇总展示。JSON 中的路径类字段**不得**被解释为任意本地读路径以实施目录穿越（除文档明确行为外，不得静默 `File.Read` 攻击者可控路径）。

#### 场景：非 http(s) 的 URL 跳过

- **当** 某条任务的 `downloadUrl` 不是 `http` 或 `https`  
- **则** 导入时必须跳过该条，且不得导致应用崩溃
